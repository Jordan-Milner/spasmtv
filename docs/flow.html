SpasmTV — the whole loop · one page, no network

A fake Twitch chat that watches a real video source. Everything runs in this tab: the vision model, the chat model, the speech model. The only network traffic is a one-time model download plus the CDN and emote-set requests listed in the README. This is the map of js/main.js, workers/llm-worker.js and js/chat-sim.js.

1 · capture — what the chat is looking at

sourcecamera · ?video= file · screen share · built-in demo canvas. activeSource() picks whichever is visible.
→
tickFrame()every tickFrame ms: draw source to a 320-px working canvas. A throw here must never kill the loop.
→
motionScore()32×18 luma thumb vs the previous one → score (mean diff) + hotFrac (cells that moved a lot).
→
drawCapture()the framed preview: optional focus crop, the same pixels the model sees. Kept as prevCapture for before/after bursts.
↓
noteMotion() — scene changea change is a spike, not a level: score > sceneFloor (0.02) and > sceneSpike (3×) the rolling median of the last ~20 ticks, ≥4 s apart. Logs a scene event and yanks the chat loop forward.why: a fixed 0.055 never fired on a real drawing VOD (peak 0.054) and fired constantly on edited video.
statediffScore · diffMax · hotMax · sceneChangeAt — all in the log, so the scorer can check burst correlation.
↓

2 · vision — the frame becomes a sentence

tickCaption() → sendCaption()throttled; skipped while a wave is running. Posts the capture to the worker.
→
worker: caption brainthe same VLM as chat (or Omni). Caption prompt, not the chat prompt — no grammar guard, so it can describe.
→
reactionSeed(caption, 3)chat never gets the caption. It gets ~3 content words from it — the seed it must react to instead of restating.
→
state.caption → ctx.sceneplus extractFacts() → the fact ledger, so chat can remember what the streamer is.
↓

3 · cadence — when chat talks, and as whom

chatLoop()decides the shape of this beat: pileOnBurst() right after a change (3 lines + sometimes a chant), a single line for the rest of the pile-on window, else planBurst().
→
gappileOnGap() 0.9–1.6 s during a wave → breatherGap() right after → nextGapMs() × MOOD_GAP[mood] normally (a purge quiets the room).
→
fireLine()pick a viewer by weight → pick a kind (gateKind: reaction, banter, backseat, meta, question, greeting, reply, callback, emote, copypasta, banreact, spot) → free line or GPU line.
↓ free — no GPU call ↓
templatesemote fills, chants, copypastas, canned lines from a real VOD corpus, dead-chat mood lines. templateRecent keeps them from repeating.
GPU budgetif pendingChat ≥ maxPending the line is dropped, not queued — a queued line is stale chat.
personaFor(viewer, kind)this viewer's vibe for this line: the archetype hint, or a spot/timeout override. Goes into the prompt as ctx.persona.
ctxscene · sceneChange · speech · userMsg · facts · emotes · ban · culture · bit · replyTo · styleExamples · recent. This object is the prompt's inputs.
↓

4 · language — one chat line out of the model

CHAT_PROMPT_PARTS()fixed order: role + length → scene seed → changed flag → react-don't-describe → kind instruction → the one quoted line (reply/ban/bit/culture/speech/facts/emotes/persona/style) → "write only the message".every label here is vocabulary the model can copy back — see the leak table below.
→
generate()grammar guard on (phones always): a logits processor makes @ * – “ ” unsampleable. Temperature / rep-penalty bumped when the recent ring looks looped or the pass is a retry. Image only on a change.
→
toChatLines()strip role prefixes, quotes, bullet junk; cap at maxWords.
→
keep()the reject list — 12 filters, below. First pass empty → one retry at higher temperature; if that dies too the line is simply lost.
↓

keep() — the reject list, in order

  1. tooSimilar vs the recent ring — the anti-echo-loop gate (0.75).
  2. tooSimilar vs the style examples — don't paste a real VOD line back verbatim (0.8).
  3. echoesScene — the caption paraphrased back is not chat.
  4. tooSimilar vs the persona — the vibe description is not a message.
  5. tooSimilar vs the quoted line — a reply must not be the thing it replies to.
  6. keysmash — vowel-shape test, the 450M's degeneration mode.
  7. META_NEG — "I can't help you with that" style refusals.
  8. unsafeLine — slurs, sexual or body talk, self-harm, plus jab-emotes (EMOTE_BLOCK). A real person is on camera.
  9. personaLeak — the archetype brief or the prompt coming back as chat.
  10. junkLine — invented @handles (they may be real people), digit runs, symbol soup.
  11. echoesSpeech — the streamer's words repeated back.
  12. softGenderDamp — half of the strong gendered guesses about whoever is on camera get dropped.

The filters are a net, not a fix — what the prompt is feeding back

Measured on the 2026-10-28 fast-brain run: 122 generate() calls for 48 kept lines — 44 first passes died in keep(). Every death is a second GPU call for one line, and the shapes it kills are almost all echoes of the prompt's own wording:

prompt linewhat the model said
On screen, roughly: …"on screen random thing coming up" · "onscreen hugs"
Something on screen just changed."on screen just changed…" · "just changed something"
Your vibe: the hype man"HYPEMAN" · "reacts like a regular…" · "troll replay in cartoon cap draw"
React like a viewer who has been here for hours"Reaction like a troll says nothing."
never more than 12 words"max 12 words hey"
no quotes, no hashtags, no emoji faces"No emotes allowed, keep your voice"
never restate these instructionsrestating the instructions

Small instruction-tuned models copy the words nearest the output and ignore negations ("never mention colors" supplies the word colors). So the fix is upstream: fewer words, positive phrasing only, no plain-English labels on the data lines, and the persona described as behaviour rather than a nameable noun. keep() stays as the net — a prompt can be changed by a tuning slider, the net can't be talked out of the job.
